# UI components

## Layout at a glance

```text
src/
  theme/      tokens.ts (LIGHT-ONLY design tokens) · styles.ts (composed-style registry) · ThemeContext.tsx (provider + useTheme/useStyles)
  ui/         primitives.tsx (Button/Modal/Scrim/MenuItem/…) · Icon.tsx + iconNames.ts (line icons) · BlockArt.tsx (dispatch + AMP_FORM_ICON) + blockart/ (procedural SVG amp/cab/pedal art, split per family — amps/ampsCombo/ampsHead*, mics/micBodies*, pedals/pedalsMotif*/pedalsSpecial/pedalKnobs, forms/formsPedal/formsRack, parts/partsCloth/partsPanel, shared.ts + sharedIds/sharedTones/sharedCloth, cabs.tsx, blockColors.generated.ts)
  lib/        invoke.ts (typed Tauri-command wrappers) · commands.ts (the `Commands` registry the wrappers and test mocks are typed against) · types.ts (hand-written mirrors of Rust structs) · format.ts · gates.ts · shared hooks useDeviceLoad.ts / useAutoAdvance.ts (run-wizard auto-advance) / usePickedRows.ts (Doctor setup-step bulk-pick selection)
  models/     catalog.ts (taxonomy) · blockArt.ts (resolvers) · blockArtCatalog/ (the catalog rows, one file per category) · tmp-model-guide.json (+ its bundled `.slim.json` projection) — the model-catalog DATA layer the CatalogView reads, NOT a view folder
  views/      level/ · doctor/ · copy/ · songs/ · settings/ — feature folders, one component per file + a barrel index.ts; flat views (CatalogView, PresetList, SignalChainView…) sit directly under views/, their pieces in views/catalog/ (ModelCard · ModelTile · ModelTags · DetailBar · useCatalogFilter · catalogArt) and views/signalChain/ (stripTypes · BlockTile · EndpointNode · DiamondNode · Wire · EmptyLane · SplitGroup/ForkTail/JoinHead · LaneBracketCap · useLaneBracket). ONE exported component per file and NO import cycles among views modules — both enforced by `__tests__/viewsModuleShape.test.ts` (a pure helper or a type a component and its siblings share goes in a .ts module, e.g. `copy/copyModel.ts`'s `EditMode`, `level/leveling.ts`'s `PresetRow`/`OUTCOME_TONE`/`buildSetupChoices`). Multi-step state is a reducer or one tagged union, not a set of flags: `copy/copyFlow.ts` (choose | edit | saving), `settings/useCalibration.ts`; page state lives in a `use*` hook beside the page (`settings/useSettingsStore`, `songs/useSongsDevice`, `level/useSetupRows`).
  views/overlays/  the multi-step WIZARD — LevelingWizard (routes each stage to its full-page component in `views/level/` — SetupPage/RunPage/SummaryPage, sharing `LevelPage`'s chrome), `WizardShell` (the centered-modal frame; its pieces `WizardHeader` · `StepRail` · `WizardFooter` · `WizTitle` each in their own file), `WizardPage` (the ONE full-page wizard frame — page + step rail with `steps` and an optional `back` + the Pick portal target — under `LevelPage` and the Doctor's Set up / Results pages), plus the Pick-family dropdown machinery (`Pick`, `usePickAnchor`, `PickPortalMenu`, and the ONE trigger `PickTrigger` + ONE option row `PickListRow` that `Pick` and `FlatLevelPick` share). (The Bulk Block Edit `overlays/bulk/` wizard was DELETED — superseded by the Copy tab.)
  App.tsx     shell routing the 6-tab IA (Level / Doctor / Copy / Songs / Catalog / Settings)
  __tests__/  setup.ts (global invoke mock + jsdom shims) + *.test.tsx
```

## Primitives, Icon, and block art

- **Primitives** live in one file, `ui/primitives.tsx`, imported directly (no index barrel), in look B: `Button` (kinds `primary` · `secondary` · `plain` · `link` · `danger`, sizes `sm` 22 · `md` 28 · `lg` 32, `busy` adds a spinner and disables; `ghost` is a PERMANENT alias of `secondary` because the frozen `ActiveSignalChainView` renders it, `warn` an alias of `danger` until the clean-up step, and `bare` is NOT a B kind but the no-padding native-button reset behind clickable rows and cells), `Modal` (the button-bearing confirm shell in Dialog's look; its backdrop is inert), `Toast` (bottom-centre, white), `Checkbox` (a REAL `<button role="checkbox">` with an accessible name, wrapped in a `<label>` with its words unless `labelHidden`) and `CheckboxMark` (the aria-hidden box for the legacy rows whose own row button carries `role="checkbox"` — never nest a control in a control), `Radio`, `Toggle` (26×16), `MenuItem`/`MenuDivider`, `SearchInput`, `TextField`/`TextArea` (label above), `Notice` (the one inline message: info / caution / danger, one action, optional close), `AlertBanner` (kept for its free-form callers until they move to `Notice`), `SegmentedControl` (one look; `size="sm"` for a sort control) and `Slider`. Stand-alone `ui/` files: `Dialog` (the ONE DS dialog shell — `DialogHeader`/`DialogBody`/`DialogFooter` slots, sizes `xs` 380 · `sm` · `md` · `lg`; it stays BUTTON-FREE, so the confirm shell lives in primitives and the import goes one way), `Menu` (the ONE anchored dropdown/context menu; roles `menu` · `listbox` · `dialog`, `align`, and `contentKey` to re-place a list whose rows land late), `Select` (the ONE dropdown — it always shows the value that will be used: a stale value shows itself, never `options[0]`; `""` shows the placeholder in the `attention` look; "for all" selects show "Mixed"; `selectValue.ts`'s `resolveSelectValue` tells a caller which case it is), `List.tsx` (`Group` · `Row` · `Caret`), `Badge` (five tones; `Tag` is a mapping shim over it until call sites move), `Footer` (the ONE bottom bar; `ActionBar` is a re-export), `PageHead`, `Steps`, `PageState` (whole-content device/app states), `SplitView` (sidebar + content), `LoudnessMeter` (the run's one meter, no numbers), `Meter` (the CPU meter: a budget-relative 40×4 bar + figure, "Over" by `overCpuBudget` — the device's rounding rule, so exactly 76.5 is over; deliberately NOT `ProgressBar`, whose 0.4s transition would lag the paint), `ProgressBar`, `Spinner`, `Dot` (tones), `SlotLabel` (Inter, tabular numbers), `PaneEmpty` (the look B empty state; renamed `EmptyState` once the device view of that name becomes a `PageState`), `Rail`/`RailItem`/`RailLabel` (the sidebar pieces), `InlineEdit` (the ONE inline text editor — Enter/blur commit, Escape cancels), `ReadingPill`, `ConfirmBar`, `RunFooterStatus`, `RunRow`, `SetupGroupHeader`/`PresetOptionRow`/`ApplyToBar` (legacy scaffolds that go as their screens move to `Group`/`Row`/`Footer`), and the songs-table pieces `views/songs/{ListHeader,SongRow}.tsx`. Use them before hand-rolling — a popover/context menu is `ui/Menu` (fill with `MenuItem`/`MenuDivider`), a dialog/overlay is `Dialog`, a dropdown is `Select`, a search/filter box is `SearchInput`; never hand-roll a `Scrim` + absolutely-positioned panel (that was extracted into `Menu`). **DS bar (Pedro's standing brief):** for cross-cutting UI prefer ONE tokenized component over per-instance wrappers; the DS owns padding/chrome (don't hand-set padding); use the look B tokens, never raw px or magic numbers.
- **One bottom-bar style across the app — reuse `ui/Footer`** (`ActionBar` is its old name, re-exported). It's a `{ left, right }` two-slot bar (56 high, `0 16px`, a `border` rule on top, `window` fill; the right group is pushed right even when the left is empty); the Copy steps, the Presets selection footer (`ContextFooter`), Settings and the wizard's `WizardFooter` all render through it. Don't re-roll a per-view footer with its own height/padding.
- **Icons** are `<Icon name="plus" size={14} stroke="currentColor" />` from `ui/Icon` — a fixed union of line-icon names. Never paste raw emoji/symbol chars as icons. Adding a NEW icon name is a 3-file edit: the `ICONS` array in `ui/iconNames.ts` + a `case` in `ui/Icon.tsx` + bumping the hardcoded `ICONS.length` count assertion in `__tests__/DSPrimitives.test.tsx` (same count-oracle pattern as the catalog test in step 5) — miss the count bump and Vitest goes red on the gate.
- **Device block art** (amps/cabs/pedals/mics) renders through the procedural SVG engine: `ui/BlockArt.tsx` dispatch + `ui/blockart/*`. **Never render Fender product photos** — the 315 copyrighted PNG tiles were removed on purpose; render SVG art, never an `<img>` photo tile. `BlockArt` takes an optional `form` (combo|head|half_stack); for amps it picks the chassis (`AMP_FORM_ICON`) the per-id glyph can't, because one `block_id` is catalogued under BOTH combo and head — thread `form` through when a row's form is known. Device FenderIds carry cab/IR/convolution suffixes the catalog omits — resolve via `models/blockArt.ts` `resolveBlockArt` / `models/deviceId.ts` `resolveDeviceId` (check-first-then-strip + a `+NoFx` bridge), which MIRRORS Rust `is_amp_model_id`; never hand-roll suffix stripping (greedy-strip breaks the catalogued-with-suffix reverb amps). See `.claude/rules/leveling-dsp.md` (amp-id matching) and `.claude/rules/models-catalog.md` (block-art resolution). **Every BlockArt-feeding path must pass the FULL art prop set** (`icon`/`tone`/`lab`/`variant`/`footswitch`/`bodyColor`/`accentColor`/`panelColor`): there is ONE shared adapter, `models/blockArt.ts` `blockArtTile(model)`, that every signal-chain strip caller consumes (`ActiveSignalChainView.toStripBlock`, `copy/CopyPath.mkTile`) — the Catalog (`CatalogView`) is the reference full-prop caller. A caller that cherry-picks props (or a new art field wired into only some callers) silently renders the DEFAULT: a Boss pedal got the round footswitch instead of its plate, FX-loop tiles lost their loop number, and the 8 Fender reverbs lost the accent chassis — all on the strip but right in the Catalog, because no test asserted strip↔Catalog prop parity. Guard a new caller with the mock-`BlockArt` prop-capture test (`testing.md`).
- **Strip amp/cab CREATE decision is DEVICE-DRIVEN; catalog `form` only VETOES the combo case.** `models/blockArt.ts::nodeTileArt(model, cabSimId, isCombo)` (3-arg, **`isCombo` REQUIRED — no default**) is the single branch every strip caller routes through: a standalone `ACD_CabSimTMS` block is named from its `cabSimId` (and `views/stripExpand.ts::expandDualCab` splits it into TWO parallel cab tiles when `cabSim2Enabled` + `cabSimId2`); a **head-form** AMP node carrying a `cabSimId` (e.g. preset 003's HIWAY `…CabIR`) becomes ONE head-over-cab tile via `ampCabHalfStack` → `HalfStackArt`; a **combo-form** amp's `cabSimId` is its built-in speaker, NOT a stack — `catalog.ts::isComboBid(model)` (catalog `form`) sets `isCombo` and SUPPRESSES the stack so it renders as a single combo glyph (e.g. blonde '65 Twin `ACD_TwinReverb65BlondeNoFx`); a bare head (no `cabSimId`) is a plain glyph. `cabSim2Enabled` on an AMP node means dual-MIC on ONE cab, NOT a dual cab. **Catalog `form` is load-bearing here BUT one-directional:** it may SUPPRESS a stack for combos (`isComboBid`, allowed), but must NEVER CREATE a cab split — the deleted `models/halfStack.ts` keyed _splits_ on `form` and drew phantom cabs onto bare heads; never resurrect that. Split creation stays keyed on device `cabSimId` presence. The 3rd `isCombo` arg is required precisely so a new strip caller can't silently omit it and re-stack every combo.
- **Device-returned strings are NOT unique — never use one as a React key.** IR names, preset displayNames, and saved-block names can collide (the device returned duplicate-named user IRs); a key like `` `ir:${name}` `` then collides → React reuses / can't swap the subtree, which masquerades as a navigation/state bug (it cost real debugging time before the duplicate-key console warning gave it away). Prefix with the array index (`` `ir:${i}:${name}` ``) or a stable id.
