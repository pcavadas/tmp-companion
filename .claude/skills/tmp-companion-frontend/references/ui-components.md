# UI components

## Layout at a glance

```text
src/
  theme/      tokens.ts (LIGHT-ONLY design tokens) · styles.ts (composed-style registry) · ThemeContext.tsx (provider + useTheme/useStyles)
  ui/         primitives.tsx (Button/Modal/Toast/Checkbox/Notice/TextField/MenuItem/…) · Icon.tsx + iconNames.ts (line icons) · BlockArt.tsx (dispatch + AMP_FORM_ICON) + blockart/ (procedural SVG amp/cab/pedal art, split per family — amps/ampsCombo/ampsHead*, mics/micBodies*, pedals/pedalsMotif*/pedalsSpecial/pedalKnobs, forms/formsPedal/formsRack, parts/partsCloth/partsPanel, shared.ts + sharedIds/sharedTones/sharedCloth, cabs.tsx, blockColors.generated.ts)
  lib/        invoke.ts (typed Tauri-command wrappers) · commands.ts (the `Commands` registry the wrappers and test mocks are typed against) · types.ts (hand-written mirrors of Rust structs) · format.ts · gates.ts · shared hooks useDeviceLoad.ts / useAutoAdvance.ts (run-wizard auto-advance)
  models/     catalog.ts (taxonomy) · blockArt.ts (resolvers) · blockArtCatalog/ (the catalog rows, one file per category) · tmp-model-guide.json (+ its bundled `.slim.json` projection) — the model-catalog DATA layer the CatalogView reads, NOT a view folder
  views/      level/ · doctor/ · copy/ · songs/ · settings/ — feature folders, one component per file + a barrel index.ts; flat views (CatalogView, PresetList, SignalChainView…) sit directly under views/, their pieces in views/catalog/ (CatalogRail · CatalogBar · ModelWall · ModelCard · ModelTile · DetailBar · useCatalogFilter · catalogLabels · catalogArt) and views/signalChain/ (stripTypes · BlockTile · EndpointNode · DiamondNode · Wire · EmptyLane · SplitGroup/ForkTail/JoinHead · LaneBracketCap · useLaneBracket). ONE exported component per file and NO import cycles among views modules — both enforced by `__tests__/viewsModuleShape.test.ts` (a pure helper or a type a component and its siblings share goes in a .ts module, e.g. `copy/copyModel.ts`'s `EditMode`, `level/leveling.ts`'s `PresetRow`/`buildSetupChoices`, `level/summaryModel.ts`'s `buildSummary`). Multi-step state is a reducer or one tagged union, not a set of flags: `copy/copyFlow.ts` (choose | edit | saving), `settings/useCalibration.ts`; page state lives in a `use*` hook beside the page (`settings/useSettingsStore`, `songs/useSongsDevice`, `level/useSetupRows`).
  views/overlays/  LevelingWizard, the Level flow's stage switch — nothing in the folder is an overlay any more (`SetupPage`, `RunPage` and `SummaryPage` are look B pages in the Level tab, each in `level/FlowPage` — PageHead + Steps, the page's content, a Footer; the run's Stop asks in a `Modal` whose backdrop is inert, and the Summary's words come from the pure `level/summaryModel.ts`): the old wizard chrome (`WizardShell`, `WizardPage` and their pieces) and Doctor's Pick-family dropdowns were DELETED once Doctor moved to look B pages (`doctor/` builds on `level/FlowPage` the same way; every dropdown is the DS `ui/Select`). (The Bulk Block Edit `overlays/bulk/` wizard was DELETED — superseded by the Copy tab.)
  App.tsx     shell: the Toolbar + routing the 6-tab IA (Level / Doctor / Copy / Songs / Catalog / Settings), the automatic connect (one single-flight attempt for the 3 s poll and the hotplug attach) and the connect kind → DeviceState page
  __tests__/  setup.ts (global invoke mock + jsdom shims) + *.test.tsx
```

## Primitives, Icon, and block art

- **Primitives** live in one file, `ui/primitives.tsx`, imported directly (no index barrel), in look B: `Button` (kinds `primary` · `secondary` · `plain` · `link` · `danger`, sizes `sm` 22 · `md` 28 · `lg` 32, `busy` adds a spinner and disables; `ghost` is a PERMANENT alias of `secondary` because the frozen `ActiveSignalChainView` renders it, and `bare` is NOT a B kind but the no-padding native-button reset behind clickable rows and cells), `Modal` (the button-bearing confirm shell in Dialog's look; its backdrop is inert), `Toast` (bottom-centre, white), `Checkbox` (a REAL `<button role="checkbox">` with an accessible name, wrapped in a `<label>` with its words unless `labelHidden`) and `CheckboxMark` (the aria-hidden box for the legacy rows whose own row button carries `role="checkbox"` — never nest a control in a control), `Radio`, `Toggle` (26×16), `MenuItem`/`MenuDivider`, `SearchInput`, `TextField`/`TextArea` (label above), `Notice` (the one inline message: info / caution / danger, one action, optional close), `SegmentedControl` (one look; `size="sm"` for a sort control; an option can be `disabled`, greyed and unclickable — never disable the chosen one) and `Slider`. Stand-alone `ui/` files: `Dialog` (the ONE DS dialog shell — `DialogHeader`/`DialogBody`/`DialogFooter` slots, sizes `xs` 380 · `sm` 460 · `progress` 420 (Copy's save) · `explainer` 500 (How leveling works) · `md` · `lg`; it stays BUTTON-FREE, so the confirm shell lives in primitives and the import goes one way), `Menu` (the ONE anchored dropdown/context menu; roles `menu` · `listbox` · `dialog`, `align`, `contentKey` to re-place a list whose rows land late, and `anchor` for a trigger the caller can't wrap — Copy's block menu on a signal-path tile), `Select` (the ONE dropdown — it always shows the value that will be used: a stale value shows itself, never `options[0]`; `""` shows the placeholder in the `attention` look; "for all" selects show "Mixed"; `selectValue.ts`'s `resolveSelectValue` tells a caller which case it is), `List.tsx` (`Group` · `Row` · `Caret`), `Badge` (five tones: neutral · good · caution · danger · accent), `Footer` (the ONE bottom bar), `PageHead`, `Steps`, `PageState` (whole-content device/app states: `views/DeviceState` — the ONE no-device page Level, Doctor, Copy and Songs render, picked by App's `NoUnitState` from the failed connect's typed kind and owning the Connection help sheet — plus `FirmwareGate`, `LoadErrorPane` and the `ErrorBoundary` fallback; none of them ever draws a backend message, which goes to the log), `SplitView` (sidebar + content) and `PageColumn` (a SplitView page's content column — the title row over a body that scrolls on its own, `maxWidth` 720 for Songs via `views/songs/SongsPage`, 640 for Settings via `views/settings/SettingsPage`), `LoudnessMeter` (the run's one meter, no numbers), `Meter` (the CPU meter: a budget-relative 40×4 bar + figure, "Over" by `overCpuBudget` — the device's rounding rule, so exactly 76.5 is over; deliberately NOT `ProgressBar`, whose 0.4s transition would lag the paint), `ProgressBar`, `Spinner`, `Dot` (tones only: good · caution · danger · neutral · working; hollow = waiting), `SlotLabel` (Inter, tabular numbers), `EmptyState` (the look B in-pane empty state), `Toolbar` (the one top bar: centred segmented-style tabs with `aria-current="page"`, a right-aligned status) and `DeviceStatus` (its readout — `state` connecting · connected · untested · busy · off, a Dot or spinner + one short phrase, no hover titles), `RailItem`/`RailLabel` (the sidebar pieces inside a `SplitView`: no icons, the shown item carries `aria-current`; `RailItem indent` is a child row, 22 px in — Catalog's Effects subcategories), `MoreMenu` (a row's or a page's ⋯ button and its 180-wide `Menu`; the caller owns `open` so its row can show `rowSelected` — Songs and Settings), `InlineEdit` (the ONE inline text editor — Enter/blur commit, Escape cancels; its optional ✓/✕ carry no hover titles), and the songs-table row `views/songs/SongRow.tsx`. Use them before hand-rolling — a popover/context menu is `ui/Menu` (fill with `MenuItem`/`MenuDivider`), a dialog/overlay is `Dialog`, a dropdown is `Select`, a search/filter box is `SearchInput`; never hand-roll a `Scrim` + absolutely-positioned panel (that was extracted into `Menu`). **DS bar (Pedro's standing brief):** for cross-cutting UI prefer ONE tokenized component over per-instance wrappers; the DS owns padding/chrome (don't hand-set padding); use the look B tokens, never raw px or magic numbers.
- **One bottom-bar style across the app — reuse `ui/Footer`**. It's a `{ left, right }` two-slot bar (56 high, `0 16px`, a `border` rule on top, `window` fill; the right group is pushed right even when the left is empty); the Copy steps, the Presets selection footer (`ContextFooter`) and the Level and Doctor flow pages all render through it (Settings has no footer: its data note lives on About and updates). Don't re-roll a per-view footer with its own height/padding.
- **Icons** are `<Icon name="plus" size={14} stroke="currentColor" />` from `ui/Icon` — a fixed union of line-icon names. Never paste raw emoji/symbol chars as icons. Adding a NEW icon name is a 3-file edit: the `ICONS` array in `ui/iconNames.ts` + a `case` in `ui/Icon.tsx` + bumping the hardcoded `ICONS.length` count assertion in `__tests__/DSPrimitives.test.tsx` (same count-oracle pattern as the catalog test in step 5) — miss the count bump and Vitest goes red on the gate.
- **Device block art** (amps/cabs/pedals/mics) renders through the procedural SVG engine: `ui/BlockArt.tsx` dispatch + `ui/blockart/*`. **Never render Fender product photos** — the 315 copyrighted PNG tiles were removed on purpose; render SVG art, never an `<img>` photo tile. `BlockArt` takes an optional `form` (combo|head|half_stack); for amps it picks the chassis (`AMP_FORM_ICON`) the per-id glyph can't, because one `block_id` is catalogued under BOTH combo and head — thread `form` through when a row's form is known. Device FenderIds carry cab/IR/convolution suffixes the catalog omits — resolve via `models/blockArt.ts` `resolveBlockArt` / `models/deviceId.ts` `resolveDeviceId` (check-first-then-strip + a `+NoFx` bridge), which MIRRORS Rust `is_amp_model_id`; never hand-roll suffix stripping (greedy-strip breaks the catalogued-with-suffix reverb amps). See `.claude/rules/leveling-dsp.md` (amp-id matching) and `.claude/rules/models-catalog.md` (block-art resolution). **Every BlockArt-feeding path must pass the FULL art prop set** (`icon`/`tone`/`lab`/`variant`/`footswitch`/`bodyColor`/`accentColor`/`panelColor`): there is ONE shared adapter, `models/blockArt.ts` `blockArtTile(model)`, that every signal-chain strip caller consumes (`ActiveSignalChainView.toStripBlock`, `copy/CopyPath.mkTile`) — the Catalog (`CatalogView`) is the reference full-prop caller. A caller that cherry-picks props (or a new art field wired into only some callers) silently renders the DEFAULT: a Boss pedal got the round footswitch instead of its plate, FX-loop tiles lost their loop number, and the 8 Fender reverbs lost the accent chassis — all on the strip but right in the Catalog, because no test asserted strip↔Catalog prop parity. Guard a new caller with the mock-`BlockArt` prop-capture test (`testing.md`).
- **Strip amp/cab CREATE decision is DEVICE-DRIVEN; catalog `form` only VETOES the combo case.** `models/blockArt.ts::nodeTileArt(model, cabSimId, isCombo)` (3-arg, **`isCombo` REQUIRED — no default**) is the single branch every strip caller routes through: a standalone `ACD_CabSimTMS` block is named from its `cabSimId` (and `views/stripExpand.ts::expandDualCab` splits it into TWO parallel cab tiles when `cabSim2Enabled` + `cabSimId2`); a **head-form** AMP node carrying a `cabSimId` (e.g. preset 003's HIWAY `…CabIR`) becomes ONE head-over-cab tile via `ampCabHalfStack` → `HalfStackArt`; a **combo-form** amp's `cabSimId` is its built-in speaker, NOT a stack — `catalog.ts::isComboBid(model)` (catalog `form`) sets `isCombo` and SUPPRESSES the stack so it renders as a single combo glyph (e.g. blonde '65 Twin `ACD_TwinReverb65BlondeNoFx`); a bare head (no `cabSimId`) is a plain glyph. `cabSim2Enabled` on an AMP node means dual-MIC on ONE cab, NOT a dual cab. **Catalog `form` is load-bearing here BUT one-directional:** it may SUPPRESS a stack for combos (`isComboBid`, allowed), but must NEVER CREATE a cab split — the deleted `models/halfStack.ts` keyed _splits_ on `form` and drew phantom cabs onto bare heads; never resurrect that. Split creation stays keyed on device `cabSimId` presence. The 3rd `isCombo` arg is required precisely so a new strip caller can't silently omit it and re-stack every combo.
- **Copy's "+" gaps are the one hook into the signal-path strip.** `StripGraph.gap.render({ beforeUid, afterUid })` (with `StripBlock.uid`, both in `signalChain/stripTypes.ts`) draws `copy/GapPlus` in place of each wire between two tiles of a row or series stage and at each end of one; unset, `SignalChainView` renders exactly as before (Level never sets it). `copy/CopyPath` sets it only on a target strip while a source block is chosen, and changes nothing else in the drawing: a dual cab keeps the two parallel cab tiles `expandDualCab` draws for it. Only the upper tile carries the cab's `uid`, so its "+" before and after place the block before or after the whole cab (its trailing "+" reads "at the end" after a trailing cab), and the lower lane draws no "+". Every other strip file stays frozen.
- **Device-returned strings are NOT unique — never use one as a React key.** IR names, preset displayNames, and saved-block names can collide (the device returned duplicate-named user IRs); a key like `` `ir:${name}` `` then collides → React reuses / can't swap the subtree, which masquerades as a navigation/state bug (it cost real debugging time before the duplicate-key console warning gave it away). Prefix with the array index (`` `ir:${i}:${name}` ``) or a stable id.
