# E2E fixture coverage

The eleven presets in `scenario-presets.json` (list indices 400–410, device user slots 401–411) are the one fixture set both e2e tiers run against.
Offline they are baked into `backup-fixture.bin` and the startup snapshot; online `probe --seed-scenario` imports them verbatim into the scratch zone.
This file maps each leveling or Doctor use case to the fixture that carries it and the structural fact in the JSON that makes it reachable.
Every structural fact here is pinned by a test in `fixture_gates.rs`, so a fixture edit that drops one fails in CI with a message naming the case.
Not every carried use case is judged in both tiers: 407's 13 Doctor defect switches are judged online only, since the offline SimDevice capture returns the raw stimulus and the spectral checks have nothing to fire against.
The authoring constraints, the deliberate deviations and the tier definitions are in [`notes/e2e-fixtures.md`](../../notes/e2e-fixtures.md).

`fixture_gates.rs` parses this file: every table row's first cell is a bare integer, the Spec column stays last, rows are never renumbered (specs cite them as `// COVERAGE row N`; delete a row in place), and every `*.spec.ts` a Spec cell names must exist under `e2e/specs/` and cite that row.
Cells are separated by single spaces with no padding; keep the `prettier-ignore` markers.
