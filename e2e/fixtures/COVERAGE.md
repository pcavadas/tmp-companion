# e2e scenario fixtures — coverage matrix

The ten presets in `scenario-presets.json` (list indices 400–409, device user slots
401–410) are the ONE fixture set both e2e tiers run against: offline they are baked into
`backup-fixture.bin` + the startup snapshot, online they are imported verbatim into the
scratch zone by `probe --seed-scenario`. This file is the map from **leveling / Doctor use
case → the fixture that carries it → the structural fact in the JSON that makes it
reachable**. Every structural fact below is pinned by a test in `lib.rs`'s `fixture_gates`,
so a fixture edit that drops one fails in CI with a message naming the case. **Caveat: not
every carried use case is JUDGED in both tiers** — 407's 14 Doctor defect switches are
judged ONLINE only today, since the offline SimDevice capture returns the raw stimulus and
the spectral chips have nothing to fire against.

## The cab rule

**Every guitar amp in every fixture is a combo, an amp+cab-merged model (a cab/IR-suffixed
id), or a bare head with a cabinet block downstream in its own lane.** Enforced structurally
by `fixture_gates::every_guitar_amp_in_every_fixture_reaches_a_cab`, which walks every
complete signal path produced by the PRODUCTION routing decoder — so a head in the
pre-split trunk with a cab in each parallel lane (404's shape) passes, and a head with a cab
in a lane it never reaches does not.

## Coverage matrix

`Offline` = the SimDevice capture model can reproduce it (`sim_device.rs::model_lufs` +
`scenario-loudness.json`). `Online` = only the real device can — the offline model has no
lane summation and no measured clamp verdict for a scene knob it cannot scale.
`setFootswitchAssignment`(54)/`clearFootswitchAssignment`(55) ARE now implemented offline
(rows 17/20 flipped). A spec written offline against an `Online`-only row will not
pass; write those under the online tier.

**Loudness ACCURACY on the `Online` rows** — as opposed to the flow/plumbing every row
above tests — is closed by `scripts/level-validate.sh` (P5, external validation). Each
strict re-measure writes its own capture to a WAV plus one expectation row
(`src-tauri/src/validate_log.rs`); after the online spec loop passes, `scripts/e2e.sh`
judges those WAVs with ffmpeg's `ebur128`, independent of this repo's own `lufs.rs`.
Base, scene AND footswitch sounds are covered — `probe --measure-footswitch` closed the
footswitch capture hole, so no row is emitted as "leveled but not verified" any more.
**Honest caveat: the `doctor_apply` prescription path is NOT externally validated** — it
has no expectation-emitting re-measure, so its A/B remains judged by this repo's own
meter alone. See `.claude/rules/e2e.md`'s "External validation" section for the gate
semantics (advisory while ffmpeg is absent, a real gate once it is present and rows were
emitted) and the 0/1/3 exit contract, and `scripts/validate-hbe.sh` for the attended
standalone (Friedman HBE) run.

## Authoring constraints these fixtures obey

1. **Every amp `outputLevel` inside one sound is EQUAL.** The offline capture model's
   stored-level probe (`sim_device::stored_from_preset`) takes the FIRST `guitarNodes.G1`
   node carrying an `outputLevel`, so two amps at different values would make the modelled
   `ol_term` depend on map ordering. 400 keeps both amps in lockstep per scene; 403 keeps
   both lane amps at the same value.
2. **403's amps live OUTSIDE `G1`**, so that probe finds none and falls back to `1.0` — which
   is exactly what both amps are authored at (except the deliberate zero-authority scene).
   Written-over-stored is therefore faithful and the closed-form joint-k solve converges in
   one step.
3. **Scene overlays follow the HW overlay semantics** (`scene_jobs::scene_overlay`): Scene
   Edit ENABLED ⇒ a FULL overlay, Scene Edit DISABLED ⇒ a bypass-only overlay
   (`{bypass, bypassType}`), never materialised ⇒ NO entry. All three states appear in the
   set (rows 10–12).
4. **Size budget: < 16 KiB of serialized `presetJson` per fixture**, because a field-8
   (`presetDataRequest`) read starts truncating around 17–20 KB and every seed ownership /
   pristine probe is a substring scan over that body. `E2E Hiwatt 3S` is the ONE exemption —
   a verbatim device export already at the cliff, so its exact size is pinned instead.
   A per-scene `splitMix` alone costs ~730 B and is mandatory, so on 402 every extra overlay
   is paid eight times; that is why its scenes carry one overlay each at most.
5. **Names keep the `E2E ` prefix.** `seed_scenario::scenario_strays` matches scenario names
   to find aborted-seed leftovers, and every fixture carries `info.source_id ==
FIXTURE_SOURCE_STAMP` plus `e2e00000-`-prefixed scene uuids as the ownership markers the
   seed and teardown guards read. **Bump the stamp's `#rN` suffix on every fixture regen.**

## Deliberate deviations, and what to do about them

- **No real chorus / delay block.** The committed corpus has no device-exported
  `dspUnitParameters` map for one, and inventing a param shape is exactly what the
  "derive from real preset JSON" rule forbids. `ACD_TMSpring63` (a real map, real `mix`)
  carries the wet-mix rows; `ACD_TremoloBias` (real `noteDivision`/`tapTimeBPM`) carries the
  tempo-sync row. If a real delay map is captured off the unit later, 401 is the fixture to
  add it to.
- **The wet-mix LOUDNESS CURVE is not HW-measured.** `ACD_TMSpring63`'s param map is real,
  but no wet-mix sweep has ever been captured off the unit, so row 18's offline response
  (`sim_device::wet_mix_gain_db` — `20·log10(1 + mix)`, a monotone +6.02 dB dry→full-wet
  stand-in) is authored, not observed. It is a DELTA anchored on the authored mix and is
  exactly zero unless a run sweeps the param, so it perturbs no other row; an offline wet
  solve proves the OUTCOME plumbing, never the real preset's numbers.
- **`ACD_Boost`'s param map is the one hand-authored node** (`{bypass, bypassType, gain}`).
  Its `gain` semantics are HW-verified (fw 1.8.45 — see `param_class.rs`: base 2.5 = +2.5 dB,
  writes of 0/2.5/5/7 accepted, loudness tracked ~1:1), but the surrounding param set was not
  captured; the device fills anything missing on import.
- **A wah stands in for the "phaser with only non-level params".** `ACD_CryBabyQ535` is the
  only block in the corpus whose entire real param map classifies `Other`, which is the
  structural fact the Other-class-refusal / Other-class-absence rows need (rows 15/19; PR
  #144 retired the verify-only mode those rows used to describe — see row 15's own entry).
- **`trade_floor` and `partial_trade` (`ClampKind`) have no fixture and are not offline-e2e
  reachable.** Both describe a headroom trade that FAILED mid-flight — the base fader
  pinning its floor while holding base on target, or a dependent write not landing so the
  pair backs out — and no committed fixture authors a trade that lands short. They are
  Rust-only, pinned by `e2e_server_tests.rs`'s ⟦F2⟧
  (`a_cancel_after_a_landed_trade_returns_its_outcomes_with_the_trade_disclosed`) and
  `headroom_trade.rs`'s own unit tests. `CLAMP_MESSAGES` still carries their verbatim UI
  strings (`src/lib/types.ts`) so a future reachable fixture needs no frontend change.
- **TODO: `stored_from_preset` takes the first `outputLevel`-carrying node**, not the
  unbypassed amp for the sound under measurement — authoring constraints #1/#2 above exist
  only to compensate (lockstep `outputLevel` across a sound's amps, and 403's amps living
  outside `G1` so the probe misses them and falls back to a value that happens to match).
  Select the unbypassed amp instead (`rendered_bypass` already exists for this), then drop
  both constraints and their gate assertion.
